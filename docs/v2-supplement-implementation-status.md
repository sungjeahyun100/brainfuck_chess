# 덱체스 v2.0 추가 기물 구현 현황

> 기준일: 2026-09-07
>
> 기준 기획: [`docx/v2.0-deckchess_supplement`](../docx/v2.0-deckchess_supplement)
>
> 상태: 성문을 제외한 추가 기물 6종 구현 및 회귀 검증 완료

## 1. 범위

현재 구현 범위는 다음 6종이다.

1. 포탄
2. 희생의 성소
3. 희생양
4. 광신도
5. 성벽
6. 수리병

성문은 규칙 충돌과 상호작용 복잡성 때문에 기획 및 구현 대상에서 제외했다. 현재 기획 폴더와 기본 기물 카탈로그에 성문 정의는 없다.

## 2. 기물별 최종 구현 상태

| 기물 | 점수 / 배치 | 현재 구현 |
| --- | --- | --- |
| 포탄 | 3점 / 뒷줄 | 이동 불가. 포켓에서 적 지상 기물 위에 포획 착수할 수 있으며 착수 즉시 폭발한다. 보드 위에서는 `폭발` 능력을 직접 사용할 수 있다. 폭발은 자신과 상하좌우 한 칸의 모든 지상 기물을 제거한다. |
| 희생의 성소 | 8점 / 뒷줄 | 킹처럼 인접 8칸을 이동·포획한다. 자신을 선택해 `희생`을 발동하며, 주변 8칸의 아군 기물 중 킹을 제외한 기물을 모두 제거한다. 그 점수 합계와 8점 중 작은 값을 한도로 삼아 적 지상 기물을 여러 개 선택해 제거한다. 쿨타임은 소유자 턴 기준 2턴이다. |
| 희생양 | 1점 / 뒷줄 | 이동과 능력이 없는 희생용 기물이다. |
| 광신도 | 2점 / 앞줄 | 전방으로 한 칸 또는 두 칸 전진한다. 직접 포획되어 죽으면 그 칸에 들어온 포획 기물도 함께 죽는다. 같은 좌표의 공중 기물은 제거하지 않으며, 원거리 능력으로 제거될 때는 광신도만 죽는다. |
| 성벽 | 1점 / 앞줄 | 이동 불가. 일반 이동 포획과 포획 착수의 대상이 되지 않으며, 슬라이딩 행마와 공격 범위를 차단한다. 폭발·사격·희생 같은 특수능력으로는 제거할 수 있다. |
| 수리병 | 4점 / 뒷줄 | 상하좌우 한 칸을 이동·포획한다. 전방 3칸 중 아군 성벽이 하나 이상 있으면 나머지 빈칸을 새 아군 성벽으로 채우는 `성벽 수리` 능력을 사용할 수 있다. |

### 희생의 성소 특수 조건

- 제물은 성소 주변 8칸의 아군 기물이며 킹은 제외한다.
- 제거 대상으로 고를 수 있는 일반 적 기물은 지상 기물로 제한한다.
- 플레이어는 점수 한도 안에서 복수 대상을 직접 선택한다.
- AI는 동일한 점수 한도 안에서 별도의 결정적 조합 선택을 사용한다.
- 주변 8칸이 모두 아군 희생양으로 채워진 경우에만 적 킹을 대상으로 선택할 수 있다.
- 제출된 대상의 중복, 적격 여부와 점수 합계는 서버가 canonical action 검증 단계에서 다시 확인한다.

## 3. 엔진 및 상호작용 경계

### 기본 정의와 Chessembly

- 6종 정의는 `engine/src/pieces/default_pieces/` 아래에 분리되어 있고 기본 기물 카탈로그에 등록되어 있다.
- 단순 행마는 기존 Chessembly 문법을 유지한다.
- 다중 제거, 사망 후처리, 포획 면역, 기물 생성처럼 Chessembly만으로 표현하기 어려운 효과는 canonical action과 `endgame` 전이에서 처리한다.
- 기존 Chessembly 코드의 의미는 변경하지 않고, 추가 기물의 특수 규칙만 별도 경계에 둔다.

### 제거 처리

- 일반 포획, 포획 착수, 폭발·사격·희생 능력은 공통 제거 경로를 사용한다.
- 제거 경로는 보드 점유, 기물의 `captured/current_square/in_pocket` 상태, 포획 기록과 킹 사망 결과를 함께 갱신한다.
- 광신도는 사망 위치를 제거 결과에 기록한다. 이동 또는 착수로 포획한 기물이 그 위치에 도착한 뒤에만 해당 포획 기물을 추가 제거한다.
- 광신도와 같은 좌표에 겹친 공중 기물은 이 후처리 대상이 아니다.

### 성벽 정책

- 일반 포획 가능 여부는 `engine/src/terrain.rs`의 공통 정책에서 성벽을 거부한다.
- 특수능력 제거는 일반 포획 면역을 우회하되 기존 지형 높이 제한은 유지한다.
- 공격 맵에서도 성벽 칸 자체와 그 너머가 일반 공격 칸으로 포함되지 않는다.

## 4. UI와 서버 연동

### 기물 테스트장

- 6종 기물을 카탈로그에서 배치하고 실제 서버 엔진으로 행마와 능력을 시험할 수 있다.
- 보드 상태, 포켓, 기물 상태, 쿨타임, 탄약과 지상·공중 레이어를 피스랩 요청에 포함한다.
- 피스랩 행동은 클라이언트가 임의로 상태를 변경하지 않고 `/api/lab/apply-action`에서 canonical action을 검증·적용한 결과로 동기화한다.
- 지우개는 테스트 배치를 편집하는 도구이므로 포획이나 사망으로 취급하지 않는다. 광신도 사망 효과는 실제 포획 행동으로 시험한다.

### 희생 선택 UI

- 브라우저 기본 prompt 대신 보드가 뒤에 보이는 전용 선택 UI를 사용한다.
- 적 지상 기물을 여러 개 선택할 수 있고 각 항목에 기물 이름, 보드 좌표와 점수를 표시한다.
- 선택할 때마다 해당 칸을 보드에서 강조한다.
- 현재 제물 점수로 계산한 한도를 넘는 선택은 비활성화한다.
- 최종 선택은 `AbilityAction.target_piece_ids`로 서버에 전달한다.

### 일반 게임과 AI

- 서버의 기본 기물 타입 해석기에 6종 ID와 성소·희생양의 underscore 별칭을 등록했다.
- 따라서 싱글플레이, 멀티플레이, 봇과 피스랩이 같은 기본 정의를 사용한다.
- AI 행동 표현과 정렬은 복수 희생 대상을 포함한다.
- AI의 희생은 가능한 대상 조합 중 점수 합계가 가장 큰 조합 하나를 canonical action으로 생성한다.

## 5. 작업 중 수정한 공통 버그

### 바운싱 기물의 잘못된 반사

`take-move`가 상대 기물을 만났을 때 포획 후보를 만든 뒤 내부 기준점까지 상대 칸으로 옮기고 있었다. 뒤따르는 `edge` 조건이 그 점유 칸을 가장자리처럼 처리하여 바운싱 비숍 등의 경로가 일반 기물이나 성벽을 뚫고 반사됐다.

현재는 상대 기물을 포획 후보로만 기록하고 기준점은 이동시키지 않는다. 따라서 일반 기물에서는 정상 포획 후 경로가 끝나고, 성벽에서는 공격·이동이 모두 멈춘다. 실제 보드 가장자리와 바운싱 폰의 의도된 반사는 유지된다.

### 광신도 사망 효과

초기 구현은 문서의 “그 위치에 존재하는 기물”을 같은 좌표의 반대 레이어 기물로 잘못 해석했다. 피스랩 재현 결과 광신도를 잡고 들어온 기물이 살아남는 문제가 확인됐다.

최종 규칙은 다음과 같다.

- 직접 포획: 광신도와 포획 기물이 함께 사망한다.
- 원거리 제거: 광신도만 사망한다.
- 같은 좌표의 공중 기물: 생존한다.

## 7. 회귀 테스트와 검증 상태

추가된 주요 회귀 범위는 다음과 같다.

- 6종 정의의 점수·배치 영역과 카탈로그 등록
- 포탄의 적 기물 위 착수와 즉시 폭발
- 성벽의 일반 포획 면역과 특수능력 제거
- 성벽에서 슬라이딩 공격 및 바운싱 반사 중단
- 희생의 성소의 아군 킹 제외, 복수 대상 점수 검증과 8희생양 킹 조건
- AI의 제한된 희생 대상 조합
- 광신도 직접 포획 시 포획 기물 동반 사망 및 같은 좌표 공중 기물 생존
- 수리병의 전방 성벽 보충
- 피스랩 canonical 행동 적용 및 광신도 사망 후처리

프런트엔드 빌드에는 기존의 500 kB 초과 청크 경고가 남아 있으나 빌드는 성공했다.

## 8. 현재 남은 범위

- 성문은 현재 계획에서 제외되어 구현하지 않는다.
- 이번 작업은 추가 기물 규칙과 필요한 공통 경계 보완에 한정했다.
- 별도 밸런스 조정, 신규 게임 모드 또는 Chessembly 문법 확장은 포함하지 않았다.
